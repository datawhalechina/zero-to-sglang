# 第 3 章 前向与生成（代码实现）

前两章从系统外部追踪了一条请求。本章进入计算本身：输入 token IDs，经过 Attention、MLP 和归一化得到 logits，再把一个新 token 接回输入。我们手写一个支持普通全量注意力的 dense Qwen3，先用随机小模型验证数学，再通过可选入口加载预训练权重。这里不会调用 Transformers 的 `forward` 或 `generate` 来代替教学实现。

本章对应[概念篇](./第3章_前向与生成.md)，完整程序位于仓库根目录下的 `examples/part2/forward.py`。权重加载单独放在 `runtime.py`，调度和投机解码会复用同一个模型接口。对照 mini-sglang 时固定使用 [9a91cfa](https://github.com/sgl-project/mini-sglang/tree/9a91cfafe754aa85daee49998176275667eb58f2)，避免函数随主分支变化。本文代码是教学实现，不是从该仓库截取的服务端代码。

## 1 本章学习目标

完成本章后，你将能够：

1. 写出 Qwen3 的单层前向，标出每一步的张量形状。
2. 正确处理 GQA、Q/K Norm、RoPE 和因果掩码。
3. 从 logits 实现贪心、温度、top-k、top-p 采样和生成终止。
4. 用同权重 logits 对齐与因果性测试定位错误。
5. 验证全量重算和 KV Cache 增量前向一致，为下一章准备基线。

## 2 先运行一个最小闭环

### 2.1 环境和文件

以下命令都在 **zero-to-sglang 仓库根目录**执行。使用 Python 3.12；默认实验只需要 CPU，不下载任何模型权重。

```bash
python3.12 -m venv .venv
source .venv/bin/activate
python -m pip install -r examples/part2/requirements.txt
python -m examples.part2.forward
python -m pytest examples/part2/tests -q
```

依赖固定为 PyTorch 2.8.0、Transformers 4.57.1 和 pytest 8.4.2。Transformers 用于独立参考模型和可选的权重、分词器加载。默认 `Config()` 只有两层、64 个词表项，运行结果是 token ID 列表；随机权重没有语言能力，不能用是否生成通顺文本判断实现正确性。

| 文件 | 阅读重点 |
| --- | --- |
| `examples/part2/forward.py` | 模型、概率处理、生成循环；首先读 `Qwen3.forward` 和 `generate` |
| `examples/part2/runtime.py` | 可选的 Qwen3 权重及 tokenizer 加载 |
| `examples/part2/tests/test_tutorials.py` | 同权重对齐、因果性、缓存、采样与终止测试 |

### 2.2 预训练模型入口

需要观察真实文本时，可运行：

```bash
python -m examples.part2.forward \
  --model Qwen/Qwen3-0.6B \
  --prompt "用一句话解释自回归生成。" \
  --max-new-tokens 32
```

这一步需要联网下载权重，也可以将 `--model` 换成本地 checkpoint 目录。加载器使用 CPU FP32；仅约 0.6B 参数本身就需要约 2.4 GB，加载过程、激活和 logits 还需要额外内存。完整模型适合短提示词验证，不适合在本例中做长上下文性能实验。独立脚本也可调用 `load_pretrained(path, revision=...)` 固定模型版本。

聊天提示词通过模型自己的 `apply_chat_template` 产生，并显式关闭 thinking，以便初次运行直接观察回答。`runtime.py` 借助 Transformers 读取权重，在 meta device 上构建教学模型后用 `strict=True, assign=True` 装载；实际前向仍走本章实现。普通全量注意力以外的 RoPE scaling、滑窗和带偏置变体会被拒绝，不默默套用错误的结构。

本文的验证包括离线小模型和本地临时 checkpoint 加载；**没有将真实 0.6B 下载推理或 GPU 性能作为已完成的验证**。

## 3 沿着张量形状写前向

### 3.1 从 ID 到 logits

令 `B` 为 batch size，`T` 为本次输入长度，`C` 为隐藏维度，`Hq`、`Hkv` 分别为 Q 和 KV 头数，`D` 为每个头的维度，`V` 为词表大小。

| 操作 | 输入 | 输出 |
| --- | --- | --- |
| Embedding | `[B, T]` | `[B, T, C]` |
| Q 投影、分头 | `[B, T, C]` | `[B, Hq, T, D]` |
| K/V 投影、分头 | `[B, T, C]` | `[B, Hkv, T, D]` |
| 注意力得分 | Q 与全部可见 K | `[B, Hq, T, S]` |
| 合并注意力头、输出投影 | `[B, Hq, T, D]` | `[B, T, C]` |
| 最终 Norm、LM Head | `[B, T, C]` | `[B, T, V]` |

没有缓存时 `S=T`；有缓存时 `S=past_len+T`。特别注意，Qwen3 的 `Hq * D` 不必等于 `C`。例如 0.6B 配置中的隐藏维度为 1024，Q 头数为 16，head dimension 为 128。因此 Q 投影输出应为 2048，而不是凭经验固定为 1024；输出投影再把它变回隐藏维度。

`Qwen3.forward` 的外层非常直接：Embedding → 逐个 `Block` → 最终 RMSNorm → LM Head。参数名称与参考实现保持一致，方便把完全相同的权重放进两个模型比较；名称相同并不代表调用了参考实现的计算。

### 3.2 一个 Block 的两条残差支路

下面是教学实现中的核心计算，变量 `x` 在两条支路之间更新：

```python
attention, cache = self.self_attn(self.input_layernorm(x), positions, allowed, past)
x = x + attention
return x + self.mlp(self.post_attention_layernorm(x)), cache
```

RMSNorm 先在 FP32 中计算平方均值，再将归一化结果转回输入类型，与可学习缩放参数相乘。它没有均值中心化操作，不能直接换成默认 LayerNorm。

MLP 采用门控结构：一条线性投影经过 SiLU，逐元素乘以另一条线性投影，再投影回 `C`。两条输入投影的输出都是 `intermediate_size`；相乘不是矩阵乘法。Norm 的位置和残差相加的顺序都属于模型定义，改动后即使形状相同也不是同一个模型。

### 3.3 GQA 与 Q/K Norm

Q 的头数可以多于 K/V。教学实现先保留 `[B,Hkv,S,D]` 的 KV，再用 `repeat_interleave` 按组展开到 Q 的头数。真实内核可以直接复用同一组 KV，避免物理复制；此处展开是为了让普通矩阵乘法能直观展示公式。

Qwen3 还分别对每个 Q/K 头做 RMSNorm，归一化维度是最后一维 `D`。先做投影、分头、Q/K Norm，再施加 RoPE。遗漏这个 Norm，或把归一化放在整个隐藏维度上，通常不会触发形状异常，却会导致 logits 对齐失败。

缓存保存的是展开 GQA 之前的 K/V，而且 K 已经过 RoPE。这样既保留原始 KV 头数，也不会在下次读取缓存时重复旋转历史 K。

### 3.4 RoPE 和因果掩码

`rope` 根据逻辑位置生成角度，将向量的前半与后半组合旋转。这里采用 Qwen 对应的 half-split 约定，不能在相同权重下随意换成相邻偶奇维交错旋转。

因果掩码要求 key 的位置不大于 query 的位置。对于缓存了 5 个 token、此次输入 2 个 token 的情况，两个 query 对应位置 5、6，允许访问的 key 范围分别为 `0..5` 和 `0..6`。不能直接使用一个没有偏移的 `2 × 7` 左上角下三角矩阵。

本例把掩码写成两层条件：物理 key 索引不能超过当前 query 的物理索引，且 key 必须是有效 token。`attention_mask` 覆盖历史与本次输入，用累计有效 token 数构造逻辑位置，因此批处理中的 padding 不会增加 RoPE 位置。

padding query 的输出会被丢弃，但其 softmax 也不能全是负无穷，否则可能产生 NaN。代码仅为这类无效 query 保留一个安全位置；有效 query 仍然严格遵守因果条件，不会看到 padding 或未来 token。

## 4 从 logits 写到生成循环

### 4.1 最后一个位置预测谁

输入 `[a,b,c]` 得到三个位置的 logits。它们分别预测 `a`、`a b`、`a b c` 之后的 token。因此下一步要使用 `logits[0,-1]`，不能把三个位置的 argmax 全部当成新增输出。

`generate` 每轮执行四步：前向 → 选出一个 token → 检查终止 → 追加到输入。模型一次输出全序列 logits，不代表可以把未来几个生成步骤并行展开；第一个新 token 尚未确定时，第二步的条件也尚未确定。

函数只返回**新生成 token**，并包含终止 EOS。文本解码时可以用 `skip_special_tokens=True` 隐藏 EOS。`max_new_tokens=0` 不调用模型；本例要求非空 prompt，空输入应由调用方决定是否加入 BOS。

### 4.2 采样顺序和截断边界

温度为零时直接 `argmax`，避免除零。温度大于零时，`probabilities` 依次执行温度缩放、top-k、top-p，随后对保留下来的分布重新归一化。

top-p 的常见错误是删除第一个让累计概率达到阈值的 token。设降序概率为 `[0.6,0.3,0.1]`，阈值为 0.8，应保留前两个 token，重新归一化为 `[2/3,1/3,0]`。代码用“当前 token 之前的累计概率是否已经达到阈值”判断删除，因而不会误删边界 token。

top-k 与 top-p 同时开启时，top-p 基于 top-k 后重新归一化的分布计算。不同采样库可能采用不同组合语义；比较输出前，应先确保参数定义相同。本章不宣称与所有服务端采样器逐随机数一致。

### 4.3 两种终止条件

采样出的 token 等于 `eos_id` 时停止；未遇到 EOS 时最多生成 `max_new_tokens` 个。二者都要在每个新 token 提交时检查。prompt 中已有 EOS 不会自动导致本例停止，因为输入可能包含对话轮次边界；真正的终止判断针对新增输出。

函数接受可选 `torch.Generator`，方便可复现实验。对随机采样，固定 seed 只约束特定设备和调用顺序下的随机数消费，并不意味着不同算法一定产生逐 token 相同的文本。

## 5 Prefill、Decode 与下一章的接口

### 5.1 先建立无缓存基线

默认生成每次把整个已有序列重新送入模型。它很慢，但容易核验。prefill 消化完整 prompt，最后一个位置给出首个新 token；后续每次生成继续重新计算前缀。单步全量注意力的得分矩阵随序列长度平方增长，历史 token 的投影和 MLP 也被重复执行。

对于模型维度固定、关注注意力随上下文长度增长的讨论，无缓存单步注意力为 `O(n²)`，已有 KV 时单个新 query 的注意力为 `O(n)`。这不等于整个请求的所有计算都变成线性，也不意味着一定获得某个固定倍数的加速。

### 5.2 最小 KV Cache 路径

程序提供 `--cache` 开关，方便与下一章衔接：

```bash
python -m examples.part2.forward --cache
```

第一次前向输入整个 prompt，返回每层 K/V。后续只输入上次采样出的 token，与历史 KV 拼接，再计算新位置的输出。下面的接口约定也供第 6 章使用：

| 参数或返回值 | 约定 |
| --- | --- |
| `input_ids` | 本次真正需要前向的 token，形状 `[B,T]` |
| `cache` | 每层一对 `[B,Hkv,past_len,D]` 的 K/V，或 `None` |
| `attention_mask` | 历史与本次 token 的有效性，共 `past_len+T` 列 |
| `use_cache=True` | 返回包含本次输入的更新后 KV；不会缓存尚未前向的采样 token |
| `logits` | 仅对应本次输入位置，形状 `[B,T,V]` |

例如 prompt 长度为 3，第一次前向后 KV 长度为 3，采样后 token 列表长度为 4。最后一个采样 token 尚未进入 KV；下一轮将它送入模型，KV 才增长到 4。这一位置差异是后续调度与投机回滚最需要记牢的不变量。

本例使用 `torch.cat` 和普通密集张量，让缓存内容可检查。它没有分页、原位 KV 写入或融合内核；缓存的深入推导与优化由[第 4 章](./第4章_KVCache优化.md)展开。

## 6 调试、完整代码与源码对照

### 6.1 不以文本通顺作为正确性标准

首先给教学模型和 Transformers 的 `Qwen3ForCausalLM` 装载同一份随机权重，在 CPU FP32、eager attention 下比较完整 logits。测试特别选择 `hidden_size != Hq * D`，避免错误实现被刚好相等的维度掩盖。误差阈值为 `atol=2e-6, rtol=2e-5`；不同精度与后端需要重新评估容差。

其次改变输入的后半部分，确认前半部分的 logits 不变。最后逐 token、按不同 chunk 切分输入，确认拼接后的缓存输出与完整前向一致。仅比较最终 argmax 不够：两个 logits 向量可能已经明显不同，但最大元素碰巧仍然相同。

常见问题可按下面顺序定位：

| 现象 | 优先检查 |
| --- | --- |
| 无缓存已经不对齐 | 权重键、Q/K Norm、RoPE 约定、MLP 激活与残差顺序 |
| 只有开启缓存才不对齐 | 位置偏移、因果掩码偏移、历史 K 是否被再次旋转 |
| 单请求正确，组 batch 错误 | padding 有效性、逻辑位置、读取 logits 的位置 |
| 多生成或少生成一个 token | EOS 提交时机、`max_new_tokens` 是否包含 prompt |

## 7 总结与测试题

### 7.1 课程总结

我们从 token IDs 写出了可核验的 dense Qwen3 前向，并把采样与终止规则接成完整生成循环。无缓存路径提供最直观的正确性基线；缓存路径明确了“已进入 KV 的输入”与“刚采样、尚未前向的输出”之间的关系。后续更复杂的调度仍然必须保持这些语义。

### 7.2 测试题

1. 为什么 `head_dim` 不能总是写成 `hidden_size // num_attention_heads`？
2. 历史 KV 长度为 6、本次输入 3 个 token 时，三个 query 分别能访问哪些 key？
3. 为什么 GQA 缓存应该在头展开之前保存？
4. top-p 阈值为 0.75、概率为 `[0.5,0.3,0.2]` 时，应留下哪些 token？
5. 如何设计一个测试，证明模型没有偷看未来位置？为什么只看生成文本不可靠？
